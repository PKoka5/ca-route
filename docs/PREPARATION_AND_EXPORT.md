# Preparation advice and local route export

`PreparationAdvisor.advise(assessments, profile)` is a pure Java operation. It reads typed task requirements and profile facts, and returns immutable `PreparationStep` values. Skills, quest progress and gear have separate known-missing and unknown states. Unknown facts become verification steps; they never become invented game locks. Imported incomplete access metadata is grouped by activity into explicit access/condition checks.

An `ALL` expression expands its prerequisites. An `ANY` expression first uses an already satisfied branch, then a potentially satisfied unknown branch, and only then an unmet branch. With several equally classified unmet/unknown branches it deterministically chooses a smallest set of prerequisite facts and labels that choice as one supported option. This is not an acquisition/training-time optimizer. Other alternatives remain explained in the step notes. Recommended combat styles use the same known-level choice as the routing model. Hard requirements and soft readiness advice stay separate; a stronger hard target suppresses duplicate weaker soft advice within the same task.

Shared steps aggregate unique task IDs, names, activities and related points. Different skill/quest targets rise to the largest supported target in that group. Completing a preparation step does **not** promise to instantly unlock every related reward: other prerequisites and the CA's own encounter conditions still apply. Related points can overlap across several preparation steps and must not be summed as additional achievable points. Completed, excluded and deferred tasks are omitted. Training, equipment acquisition, quest duration and price are not estimated by this adviser.

`TasksTrackerRouteExporter` generates a local `COMBAT` route JSON object with deterministic IDs, ordered sections/items and separate preparation custom items. The caller must supply a completion-index -> struct-ID mapping obtained from live identity validation. Unknown, negative, duplicate or aliased selected mappings cause an explicit refusal with no JSON output. No completion bit index is guessed to be a tracker task ID. No account identity, account hash, profile version or network request is included.

The default two-argument export includes static per-stop condition checks. The optional three-argument export accepts advice computed from the **selected route tasks and the same player profile**. It refuses advice referring to unselected tasks, because a broader catalogue grouping could otherwise export an inflated target such as Magic 99 for a selected task that only needs 70. General preparation-tab advice should not be passed unchanged to that overload.

The schema was inspected from the Plugin Hub-pinned Tasks Tracker revision `dbdfdaddbdc09592e54f90056a5397df63f4e88a`: route fields `id`, `name`, `taskType`, `author`, `description`, and `sections`; each section contains `id`, `name`, optional `description`, and ordered `items`. Each item has exactly one `taskId` or `customItem`, plus optional `note`/`location`. A custom item contains `id`, `label`, optional `icon`, and `description`. Legacy `taskIds` sections are not emitted. Strategy links and exact task descriptions remain static notes; export does not change any game state.

Automated exporter tests validate field shapes, uniqueness, ID mapping/order, deterministic output and Gson round trips through compatibility DTOs matching the pinned public fields. They do **not** execute the third-party GUI importer or prove that a later Plugin Hub version accepts the same schema. Importing into the actual pinned/current Tasks Tracker plugin remains an in-client integration smoke test before a compatibility claim or release.
